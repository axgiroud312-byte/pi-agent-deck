# Agent Deck 0.9.1

修复 0.9.0 审查中复现的三个问题，并将 GPT-6 Sol、GPT-6 Luna 加入 Jev 的可选模型。保持 `Agent`、`SendMessage`、`TaskStop` 的公开参数不变。

- **扩展模型在子 Agent 中丢失**：将声明式 `registerProvider` 配置单独传入独立进程。子 Agent 保持原工具权限，不加载父扩展的工具、钩子，也不开放嵌套派遣。包含自定义函数、OAuth 回调或原生 Provider 的提供商暂不支持，会在创建 Session 和任务前说明原因。
- **补充消息重复执行**：消息增加持久 ID，恢复请求与对应轮次一起保存。队列删除失败不再导致自动重放；请求已保存、状态未提交时，重启会补齐同一轮。新消息仍按顺序处理，停止能取消尚未启动的恢复事务，旧字符串队列仍可读取。
- **其他会话的坏记录阻止新建任务**：首次建立父会话索引时跳过其他会话的坏记录；当前会话的坏记录仍会明确报错，防止把已绑定的名称误当作可用。
- **新增 GPT-6 Sol 与 GPT-6 Luna**：各提供 `off/low/medium/high/xhigh/max` 六个起始组合，与 Astra、GPT-5.6 Sol 共 23 个。按 Pi 中的实际可用性、提供商和能力筛选；Chat Completions 下的新模型只采用支持工具调用的 `off` 档，推理工具调用需 Responses。选项适用范围属于待评估策略。

扩展提供商快照属于私人认证状态，保存于个人 Pi 目录的 `agent-deck/providers/`，可能包含原配置的密钥和请求头。请与 `auth.json` 一样保护，不要提交或分享。任务文件只记录快照路径；旧任务继续沿用创建时的快照。完整说明见 [README](../README.md)。

升级后在所有打开的 Pi 中执行 `/reload`。版本更新保留用户的派遣开关、Jev 设置和角色文件。旧版已经失败且没有提供商快照的任务需要重新创建；修复不自动重跑历史任务。

验证使用隔离 Agent 目录、故障注入、真实 Pi 子进程及本机模拟模型接口。检查扩展模型的创建与继续、密钥和请求头传递、工具隔离、日志不含认证值，以及队列删除失败和恢复中断后的跨进程去重。没有调用真实付费模型或评估 Jev 选模质量。

此版继续使用 Pi 自身的 Session 和任务记录；接口是 Claude Code 风格，并不承诺 Claude Code 数据结构完全兼容。回退前请结束新版任务并处理消息队列，避免旧版忽略新恢复凭据后重复执行。
