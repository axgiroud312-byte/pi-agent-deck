# 0.9.4 · 子 Agent 停用 Astra

GPT-6 Astra 从子 Agent 的可用策略中停用。Jev、自动回退、显式模型、模型别名和角色固定值都不能再让子 Agent 使用 Astra；角色配置菜单也不再提供它。主会话自身的模型保持由 Pi 管理。

## 保留的组合

| 模型 | 用途 | 思考强度 |
|---|---|---|
| GPT-6 Sol | 非审查任务 | `high`、`xhigh`、`max` |
| GPT-6 Luna | 非审查任务 | `high`、`xhigh`、`max` |
| GPT-5.6 Sol | 仅审查任务 | `xhigh`、`max` |

共 8 个组合，非审查池 6 个、审查池 2 个。Jev 仍只决定模型和思考强度；主 Agent 决定数量、角色和分工。

子任务继承到 Astra 时，非审查角色在同一提供商中优先使用 GPT-6 Sol，其次 GPT-6 Luna；审查角色选择 GPT-5.6 Sol。思考强度按现有下限和模型能力调整。无合规配置时，在创建任务前报错；明确指定 Astra 时也直接提示修正。

## 更新与已有任务

更新后在每个打开的 Pi 中执行 `/reload`，再运行 `/agent-doctor`，确认已加载 **0.9.4** 且不需要重新加载。若仍驻留旧版本，等正在运行的任务结束后重启该 Pi 会话。

旧排队任务、已选配置和实际启动参数都会检查最新策略。旧 Astra 任务不能再次启动或继续，需要改用合规模型新建任务；已有结果和待处理文字保留，自动补充不会反复尝试被策略拒绝的任务。已经运行的进程不会被更新自动终止或换模。

Jev 的可视化配置入口、个人密钥与自动选配开关保持原有方式。详见 [配置及使用说明](../README.md)和 [选配规则](jev-routing.md)。

## 验证范围

回归验证覆盖候选过滤、继承回退、显式模型和别名、角色菜单与角色生成、关闭 Jev、旧任务续接、独立 Runner 的实际启动拦截。自动化使用受控进程和模拟服务，不使用个人密钥进行真实付费推理。
