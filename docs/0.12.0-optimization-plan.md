# 0.12.0 优化计划：明确委派与续接，只读查看子会话

## 目标

用户只与主 Agent 沟通。主 Agent 澄清关键需求、安排任务和依赖、验收并整合；子 Agent 在明确范围内执行，返回有依据的结果。本次执行结束后释放进程，任务 ID 和 Pi 子会话保留。

## 实施范围

1. 保留 Agent / SendMessage / TaskStop。Agent 新建任务；Agent({resume, prompt, description?}) 明确续接已结束任务，沿用原角色、模型和会话。运行中 resume 报错。普通 SendMessage 只补充信息，空闲时暂存，不自动启动。移除公开 delivery / reply_to，旧调用给出迁移错误。
2. 主 Agent 的工具说明统一要求任务包含目标、范围、交付和验收方法；独立工作并行，有依赖的工作顺序执行。最多 8 个活跃子任务，Jev 只选择模型和思考强度。
3. 移除子 Agent 提问与等待答复流程。范围内的技术选择自主处理，无法继续时提交阻塞原因、已完成部分和证据，交回主 Agent。结果采用简短的结构化最终报告；自然语言回退不冒充验证通过。
4. 统一面板和主 Agent 通知中的执行状态、失败原因、已完成部分、证据、验证结果与剩余工作。子 Agent 的验证报告标明来源，不等同于主 Agent 验收。
5. 控制台 Enter 打开只读子会话，显示真实用户/助手消息、工具调用和输出、实时公开输出；历史来自 Pi 会话。Esc 返回，查看不切换主 Pi 会话、不启动子进程、不阻止资源释放。删除聊天、回答、续接输入入口。
6. 修复结果保存失败阻断清理，以及错误原因被已有输出掩盖的问题。继续使用现有 Pi RPC 和短任务操作队列，不添加持久投递、自动恢复、工作树或额外调度层。

## 验证

- 新建与续接参数互斥；任务 ID/实例名称寻址；运行中不能续接；会话缺失不得创建空白替代。
- 运行中补充在工具边界送达；结束后补充不启动；明确 resume 复用会话并重置本轮结果。
- 使用真实 Pi RPC 和本地可控模型，覆盖创建、补充、结果、释放、续接、失败、停止和保存失败。
- 只读会话页显示真实消息与工具结果，打开/关闭不派发、不修改会话；失败原因在面板和通知一致。
- 回归并发 8、Astra 禁用、审查仅 5.6 Sol 且最低 xhigh、6 Sol/Luna 最低 high。
- 类型检查、相关回归测试、打包检查；更新中文 README、开发文档、发布说明并推送 GitHub。

## 升级边界

当前代码基线 0.11.0。旧会话和报告保留，不迁移正在执行的进程、不重放旧队列。新建任务采用新提示词，续接旧任务时更新插件运行约定。主会话中的其他规则仍由 Pi 正常加载。本版没有自动验收引擎；主 Agent 依据实际证据验收。

## 执行结果

上述范围已完成。完整回归 123 项通过；最终小改动相关回归 23 项通过；类型检查、真实 Pi RPC、实际 TUI 组件和打包检查通过。详见 [验证记录](evidence/0.12.0/validation.md)。旧问答模板与闲置委派模板已删除，历史数据读取兼容保留。
