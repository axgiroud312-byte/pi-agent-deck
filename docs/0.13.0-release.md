# Agent Deck 0.13.0：Pi 原生薄编排

0.13.0 把早期过于严格的多 Agent 治理实现收敛为 Pi 原生子会话的薄运行层。主模型负责判断和验收，角色提示词负责行为约束，程序只保留工具/扩展配置、独立上下文、前后台执行、显式续接、持久化和可靠清理。

## 主要变化

### 编排交给主模型

- `Agent` 工具描述动态包含可用角色、职责、工具范围、排除项、扩展数量和简短委派建议。
- 主模型自行决定是否委派、角色、数量、同轮并行、前后台和后续验收。
- 不再注入大型 system orchestration prompt，也不再随包发布专用编排 Skill。
- 简单任务可以直接完成；项目不强制固定探索—实施—审查流水线。

### 角色只配置 Pi 原生能力

- 当前字段是 `tools / disallowedTools / extensions`，以及可选 `model / thinking / timeoutMs`。
- worker 省略 `tools`，使用 Pi 默认工具。
- scout/reviewer 只排除 `edit/write`；Bash 和其他 Pi 默认工具保持可用。
- 子 Pi 使用 `--no-extensions`，只加载角色明确选择的本地扩展和内部 provider bridge。
- 内置 provider 与 `models.json` 可直接使用；扩展 provider 只有可序列化配置能桥接。原生/函数式 provider 不能传入隔离子 Pi，没有兼容模型时会在创建任务前失败。
- 删除额外工具能力表、来源鉴定、`capabilities.json` 握手和扩展预扫描；真实 Pi 加载/执行错误直接成为运行错误。

### 运行正常结束不等于业务完成

- 删除 `agent_report`、当前 `TaskResult`、结果完整性和工具证据聚合。
- 子 Agent 持续执行 Pi 原生模型—工具循环，Pi 正常 settled 即 `completed`。
- “我做不到”、阻塞说明、部分完成、空文本和无 `message_end` 的正常 settled 都可以 completed。
- 主 Agent 直接阅读最终文本和 Pi Session，根据用户要求验收或显式 resume。
- 模型、RPC、进程、扩展、持久化、超时、取消和停止仍保留为真实运行错误。

### 前台、后台、消息与续接

- 省略 `run_in_background` 或传 `false` 时前台等待保存后的结果。
- 传 `true` 时通常先返回任务 ID；若任务在初始调用返回前已经终态，则直接返回最终结果且不重复通知。
- 自动完成通知只投递给当前进程中仍活动的所属父会话；切换会话或重载后不补送，结果仍会保存。
- 两种模式共用同一启动、保存和清理路径，前台不会再收到重复后台通知。
- `SendMessage` 只补充：运行中 steer，空闲时暂存但不执行。
- `Agent({ resume, prompt })` 显式续接原 runId、Pi Session、模型和创建时配置；角色文件修改只影响新任务。

### 删除硬治理

- 删除每会话固定 8 个活跃任务上限。
- 删除工作目录实施者锁、主 edit/write 拦截和 Bash 身份推断。
- 删除任务 DAG、排队、writer lease 和旧问答等待路径。
- 删除 Astra/角色专属模型/最低 thinking 等硬政策；Jev 只在隔离子 Pi 可加载的组合中选择，有兼容候选时失败软回退。
- “同一时间只让一个实施者修改正式交付文件”保留为主模型和角色提示词的协作约定。

### 历史兼容

- 新记录版本为 v3。
- v1/v2 的旧问答、报告、租约、写权限、结构化结果和工具证据集中投影到 `legacy`，继续可读。
- 启动和浏览不会批量改写用户历史；显式 resume 才迁移当前任务，并移除旧 `agent_question / agent_report` 工具。
- 丢失或损坏的 Pi Session 不会被空白会话替代。

## 真实宿主验证

自动集成测试使用本机真实 Pi CLI 和 RPC 模式，以及完全本地的受控 provider。测试扩展 `RoleProbe` 由 Pi 实际加载，模型实际发出工具调用，扩展写入执行日志，工具结果进入下一次模型上下文并保存在 Pi Session；这不是只检查命令行参数。

组合场景覆盖：

1. 两个只读 scout 并行；
2. 一个 worker 使用本地角色扩展；
3. 两个只排除 edit/write 的 reviewer 并行使用 Bash 执行 `node --version`；
4. 原 worker 显式 resume，复用同一个 Pi Session 和扩展配置。

本地 provider 不联网、不使用真实账户额度，因此不能冒充在线真实模型质量验证。

## 已知边界

- 可序列化的扩展 provider 配置按任务保存在 Pi 个人目录，供启动和 resume 使用。快照可能包含 API key/header，任务记录只保存路径；该文件不进入项目或 npm 包，必须按私密认证状态管理。
- 原生 provider 或包含函数、`symbol`、`bigint` 的 provider 配置当前不能桥接到隔离子进程。若没有任何兼容模型，任务在创建前失败；这不是角色或模型型号硬名单。
- 后台完成通知是当前进程内的便利交付，不是持久消息队列；快速终态由初始工具结果交付，切换父会话或重载后应从 `/agents` 查看落盘结果。
