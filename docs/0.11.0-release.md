# 0.11.0 发布说明

主 Agent 负责调度和验收，子 Agent 执行并返回结果；程序自动释放进程，继续时复用原任务和 Pi 会话。

## 变化

- 保留 Agent / SendMessage / TaskStop。唯一新增输入字段是 SendMessage.delivery，取 QueueOnly 或 TriggerTurn，默认 TriggerTurn，兼容已有普通调用。
- QueueOnly 在空闲时仅暂存信息，不启动子进程或模型；TriggerTurn 复用原会话继续。reply_to 只回答当前问题，不能同时传 delivery。
- Pi agent_settled 确认执行边界；返回结果、失败、中断与进程资源状态分开。正常返回后自动关闭进程，释放槽位，主 Agent 独立验收。
- 每个主 Pi 会话固定最多 8 个活跃子任务；新建和续接共用入口，等待答复也占位；第 9 个请求报错不排队。
- 移除新运行路径的整个工作区写锁与重试等待。主 Agent 按任务依赖和共享接口安排顺序，独立任务可以并行修改不同文件。
- 派发前展示由实际启动工具列表生成的角色能力；内置 Explore/reviewer 不具有执行命令或测试的能力。
- 控制台 C 继续、M 仅发信息、A 回答问题，详情显示进程状态和暂存数量。
- Pi RPC 输入、完成与释放按任务顺序处理，避免旧进程关闭影响下一次执行；JSONL 按 LF 分帧。

进度仍只传递，问题与最终结果仍自动通知并唤醒主 Agent。Jev 仅选模型/思考；Astra 禁用，审查仅 5.6 Sol 且最低 xhigh，6 Sol/Luna 最低 high。

## 升级

等待已有任务结束后再 /reload；不迁移或强制停止升级前的运行任务。主 Pi 结束或重载时子进程结束。历史 Session 和结果保留，信息邮箱仅在当前进程中有效，退出后不重放。

此版本没有工作树隔离，也不自动判断跨文件语义冲突。分工、依赖顺序和最终整体验收仍由主 Agent 负责。
