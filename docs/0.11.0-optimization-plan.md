# 0.11.0 优化计划

目标：主 Agent 派发任务，子 Agent 在 Pi 原生会话中执行并返回结果；程序自动释放进程，主 Agent 独立验收。继续工作复用任务 ID 和 Pi 会话。

## 接口与消息

保留 Agent、SendMessage、TaskStop。SendMessage 新增可选 `delivery: "QueueOnly" | "TriggerTurn"`，默认 TriggerTurn。这是本插件扩展，与已有 reply_to 一样，不宣称是 Claude 原生字段。

| 情况 | QueueOnly | TriggerTurn |
| --- | --- | --- |
| 正在执行 | 在 Pi 接收消息的边界补充到当前执行 | 补充到当前执行 |
| 创建或选配中 | 在主进程暂存，启动时送入 | 同左 |
| 等待问题答复 | 仅补充，保持等待 | 仅补充，保持等待 |
| 本次执行已结束 | 仅放入主进程邮箱，不启动模型或进程 | 复用原会话开始新执行，带上暂存消息 |

reply_to 按当前任务、执行和问题匹配，返回到原工具调用；不能同时指定 delivery。无效、重复或过期回复报错。进度通知不唤醒主 Agent，问题和最终结果继续自动唤醒，避免依赖任务停滞。

## 执行与资源

- 使用 Pi 的 agent_settled 和最终消息结果判断本次结束，不从文字、静默时长或 agent_end 猜测完成。
- 执行状态（返回结果、失败、中断）与资源状态（启动、存活、释放中、已释放）分开。
- 保存结果后关闭子进程，确认退出再标记资源释放；无需模型判断是否关闭。等待问题时不释放。
- 同一任务的消息、结束、停止、续接顺序处理，旧进程的退出不得改变新执行。
- 停止清除问题和消息，结束当前执行；父 Pi 关闭时结束其子进程。只保留 Pi 会话和结果，不恢复或重放消息邮箱。

## 调度与能力

- 每个主 Pi 会话最多同时占用 8 个子任务槽位。创建、选配、执行、等答复、停止/释放过程占位；历史任务不占位。
- 新建和 TriggerTurn 续接都先同步占位，第 9 个请求明确失败；不增加自动排队。QueueOnly 和问题答复不另占位。
- 移除新执行路径的工作区写锁和重试排队。主 Agent 划分修改范围；有依赖或共享接口的工作顺序执行，独立任务可并行。共享目录不能自动保证语义无冲突，仍由主 Agent 验收。
- 从实际启动工具列表生成角色能力说明，派发前可见读写、命令/测试、提问能力及不可用原因；不让所有角色继承全部工具。
- 保持既有模型策略：禁用 Astra；审查仅 5.6 Sol 且最低 xhigh；6 Sol/Luna 最低 high。Jev 只选模型与思考强度。

## 实施与验收

1. 完成消息模式、原生 RPC 生命周期和并发入口。
2. 同步工具说明、角色能力与控制台的“仅发信息 / 继续工作 / 回答问题”。
3. 验证 8/9 并发边界、失败释放、停止、结束/续接竞争、问题隔离、历史结果、角色能力。
4. 用真实 Pi RPC 和本地可控模型验证派发→补充→提问→答复→完成释放→仅发信息→原会话续接；不用付费模型做测试。
5. 类型检查、相关回归、控制台交互检查后更新中文 README、开发文档、发布说明和 GitHub。

不创建工作树，不增加自动依赖图、后台消息服务、持久化回执、自动重放或版本核验。现有运行中的用户任务不强制迁移；更新在任务结束后重载生效。
